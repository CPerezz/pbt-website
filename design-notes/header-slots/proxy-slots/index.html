Give proxy slots a place in the header.

TL;DR The three EIP-1967 proxy slots take of cold storage charges and storage paths per block. Mapping them to unused header positions would remove those paths, and save another of gas under the header gas rule.

Aproposal & expectation

Upgradeable contracts read their implementation address from a fixed, hashed slot on every call. EIP-1967 standardised three such slots (implementation, admin and beacon), and today's common proxy libraries use them. Because those slot numbers are hashes, EIP-8297 puts them in the storage zone, so every proxy call opens a separate path and gains nothing from living next to the header.

The proposal: map these three slot numbers to unused header positions. Contracts can't tell the difference, and the mapping stays one-to-one. It works the same whether the header holds 32 or 64 slots. Only the slots EIP-1967 standardised are covered; the header doesn't reserve positions for any one library's own scheme.

We expected a few percent of all charges.

Cconclusion

Supported. A small special case in the key mapping covers of cold storage charges. The paths matter more than the charges: proxy reads are spread over many contracts (see the table), and each contract a block touches needs a path of its own. So the three slots spare each block paths, against for all of slots 0–63. Without a header gas rule it saves witness and paths; with one, users save gas too. ERC-7201 namespaces can't be covered the same way, since their slot numbers differ per contract.

The first 64 slots.

EIP-8297 keeps every account's storage slots 0–63 in its header. These notes test that choice, and the changes it invites, on seven months of mainnet. Each has the same three parts: A what it says and what we expected, B the data, C the conclusion.

Sample: mainnet blocks in ranges of 1,000, one every 10,000, from to : transactions. Plus the live storage of every account at block 26,300,000. A few measurements use smaller windows; each note's data part says which.

Charging those slots with the header would save of gas, storing them with the account costs clients almost nothing, and proxy slots belong there too.

The account header stem

Each account has a header stem: up to 256 leaves under one key prefix, 0x00 ‖ key_hash(address). EIP-8297 puts the basic data (nonce, balance, code size) at position 0, the code hash at 1, a 7702 delegation at 2, and storage slots 0–63 at positions 64–127. Slots from 64 up live in the storage zone, under the contract's own bucket. Running a contract always reads its header, so slots kept there come along with it.

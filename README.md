# PBT Lab — EIP-8297 Partitioned Binary Tree, interactive 3D explainer

**Live:** https://cperezz.github.io/pbt-website/

## Overview
An interactive 3D explainer of the EIP-8297 Partitioned Binary Tree (PBT). The user picks an Ethereum action (send ETH, deploy a contract, redeploy identical bytecode, EIP-7702 delegate / re-delegate / revoke, ERC-20 transfer, call a contract, clear a slot, big contract, witness proofs, one block) and steps through it. Floating windows explain each concept (hashing, key derivation, chunking, bit-by-bit trie walks, writes, root recompute) while the 3D tree shows exactly which nodes are touched. Every root is recomputed in-browser with BLAKE3 and checked byte-for-byte against the spec fixtures.

## About the Design Files
The files here started as **design references built in HTML** (a Claude Design handoff): a working prototype showing the intended look and behaviour, not production code. It has since been debugged and published as-is. Porting it to a framework (React + three.js / react-three-fiber) is future work, not yet done. The tree maths in `pbt-core.js` is framework-free and can be ported almost directly (add unit tests against `pbt-fixtures.json`).

## Fidelity
**High-fidelity.** Colours, typography, layout, window placement and animation timing are final. Every numbered item under "Open work" below is resolved or confirmed-already-fixed except #3 (a hover leader-line) and #11 (a deliberate decision, not a bug).

## Architecture
- `lab.html`: the 3D app (deep-linkable via `#trip` / `#atlas` / `#why` / `#forge`). Template markup (inline styles) + a `Component` logic class. It runs on `support.js`, a small runtime that renders `{{ }}` template holes, `<sc-for>`/`<sc-if>`, and `style-hover` attributes on React. Treat it as JSX-equivalent when porting.
- `pbt-core.js` (`window.PBTCore`): BLAKE3, keccak256, key derivation (account header, code chunk, storage), `chunkify`, `binarize` (canonical binary trie with prefix compression), `merkleize`, `witness`, `recomputeSet`, `applyWrites`, `rootOf`, `buildWorlds(fixtures)`.
- `pbt-scene-v4.js` (`window.PBTScene`): three.js scene. Radial layout by zone, instanced meshes (leaves, code tiles, stems as gems, branch tubes), styling (focus / path / ghost / ring / recomputed), labels + leader lines, camera framing per tier (`tree` / `zone` / `node`), region-aware framing so floating windows don't cover the focus.
- `pbt-beats-v5.js` (`window.PBTBeats`): the content. Builds every journey (J1–J10) as a list of *beats*. Each beat has a world snapshot `w` (+ `preW` for writes), camera tier/zone/focus, optional `walk` key, and an `fx` window spec. Window specs are data: `seq` (frames of tracks/grids/rows/bigs/checks/flow/dep with pips, auto-advance, `btn` + `run: 'world'|'flash'`, per-frame `look` camera/label cues), `walk`, `derive`, `root`, `grow`, `ledger`.
- `uploads/fixtures/`: `pbt-fixtures.json` (worlds, journeys, writes, derivation steps, expected roots) generated by `gen_fixtures.py`. `sol/combined.json` holds the solc output for MegaToken / VaultTemplate / Ephemeral.
- `docs/`: the original experience spec, scenario bible and reference board.

## Screens / Views
1. **Hero / picker**: full-bleed 3D tree slowly orbiting, action cards grouped by theme. Header top-left: Home + "Pick another action".
2. **Journey**: one beat at a time.
   - Top: caption with coloured keywords (`{b|…}` blue account, `{c|…}` amber code, `{s|…}` mint storage, `{g|…}` green hash/path, `{a|…}` header).
   - Floating window (the `fx`): **stage** mode (centred, large) for concepts. **hud** mode (docked bottom/side) whenever the tree must stay visible (walks, writes, flashes, "look" steps).
   - Left: **Layout panel**: account card (header subs 0–2, header band 64–127 = slots 0–63, storage-zone entries) or **code layout** (chunks by group, green = written now, dashed = all-zero/absent, hover ↔ leader line to the tree leaf/stem).
   - Bottom: beat rail, play/step controls, zoom tier, follow mode.
3. **Summary**: after the last beat. Git-diff colouring on the tree (green created, orange updated, red "− removed" labels, lilac rehashed). A "What changed" list per account/code group with +/~/− counts and "inspect →", pre/post root, in-browser root check, rehash cost. Buttons: Pick another action, Replay.
4. **Atlas / Why PBT**: self-paced facets (zones, header, code zone, storage zone, hash lab, witnesses, proof-size race).

## Interactions & Behaviour
- **Hash animations**: `hashTrack` cells scramble with a tag (keccak256 / BLAKE3) and then **settle and stay** on the result. Required behaviour: keccak must finish and persist exactly like BLAKE3 does in J1 (see Open work).
- **Walks**: step through the key bit by bit. Each branch highlights the chosen side, the path turns green, and it ends either "found" or "parts at bit N" against the leaf actually there.
- **Writes**: the button (`run: 'world'`) swaps to the next world snapshot with staggered appear (chunks stagger by index). New leaves get a green ring, updated ones orange. The window moves to hud so the growth is visible.
- **Flash**: lights keys one by one (`flashIv` ms), e.g. dedup checks all 23 VaultTemplate chunks, dispatcher chunks in lilac.
- **Root recompute**: a wave rehashes touched paths bottom-up (lilac), with a count of hashes / branches / leaves.
- Hovering leaves or stems shows a tooltip. Clicking an account stem or code leaf opens inspect (in the summary).
- Camera: `frameFor(beat, tier, focus)` fits the focus into the free region left after the floating window and layout panel.

## State (Component)
`mode` (hero | journey | summary | atlas | why), `ji` / `bi` (journey / beat index), `fx` (resolved window + current step), `playing`, `zoom`, `follow`, `layoutLab` / `layoutOpen`, `inspect`, `walk`, `tip`, `spec`. Worlds are immutable `Map<keyHex, valueHex>` snapshots; the scene diffs them on `setWorld`.
